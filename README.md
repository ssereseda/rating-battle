# Рейтинг-баттл

Полностью русскоязычная аркада «Выше или ниже» по рейтингам 50 сериалов Кинопоиска. React 19, TypeScript, Vite 7, Tailwind CSS 4, Motion, Lucide и PapaParse. Сервер, авторизация и ключи API не нужны. Без звуков и ограничения времени.

## Запуск

Нужен Node.js 22.12+ (рекомендуется 24) и npm.

```sh
npm ci
npm run dev
```

Открыть адрес, который выведет Vite (обычно `http://localhost:5173`). Не открывать `index.html` напрямую: загрузка CSV требует HTTP.

```sh
npm run typecheck  # проверка TypeScript
npm test           # тесты логики и пользовательских сценариев
npm run build      # production-сборка в dist/
npm run preview    # локальная проверка production-сборки
```

## Возможности

- Три жизни, сравнение настоящих числовых рейтингов, ручной переход между раундами.
- 100 очков × множитель по **новой** серии: 1–2 → ×1; 3–4 → ×1,5; 5–9 → ×2; 10+ → ×3.
- Подсказка один раз: диапазон шириной 0,5, гарантированно включающий рейтинг.
- Две замены второго сериала без потери комбо, очков и жизней.
- Щит автоматически за семь подряд, только один за сессию. Ошибка тратит щит и сбрасывает комбо.
- Семь достижений, уведомления, даты получения по московскому времени.
- Рекорд, максимальная серия, завершённые игры, общее число верных ответов в localStorage.
- Рейтинг **всех 50** сериалов после каждой завершённой игры: три сортировки, пересчёт мест, поиск, раскрытие CSV-сведений и ссылки на Кинопоиск.
- Управление с клавиатуры, фокус в диалогах, Escape, reduced motion, адаптация от 320 px.
- Локальные шрифты Manrope и Unbounded с кириллицей: внешние сервисы шрифтов не требуются.

## Данные

Единственный источник — `creative_hse_2026 - kinopoisk.csv` в корне. Исходный файл не изменён. Перед запуском разработки и сборкой `scripts/sync-data.mjs` копирует его в `public/` без изменения байтов; приложение загружает эту локальную копию. Данные не запрашиваются через API и не дополняются сведениями из интернета.

Проверены UTF-8, 50 записей, 8 русских заголовков, уникальные ссылки, диапазон рейтинга 7,4–9,0. Числа преобразуются в number, рейтинг выводится с одной цифрой после запятой, оценки — с пробелами. При неполном/повреждённом файле открывается экран ошибки с повторной попыткой.

Поле «описание» содержит **страну, жанр и режиссёра**, а не аннотацию сюжета. Приложение показывает исходное поле и отдельно выделенные из него сведения. Выдуманных описаний нет. Год сортировки — первый год периода выхода, от новых к ранним. При равном рейтинге сравниваются оценки, затем названия по русскому алфавиту. Поиск сохраняет место в выбранном полном рейтинге; смена сортировки пересчитывает места.

Постеры сохранены локально без изменения по исходным ссылкам из CSV в `public/posters/`. Встроенная карта URL связывает изображения с исходными записями; новые данные не запрашиваются. В игре их размер 72×108 на телефоне и максимум 96×144 на компьютере; на главной — 108×162. При недоступном изображении показываются название и иконка киноплёнки. Данные, постеры и шрифты входят в сборку; внешние CDN для работы интерфейса не требуются.

## Правила завершения и сохранения

Последняя ошибка сначала раскрывает рейтинг и пояснение. Нажатие «К результатам» завершает сессию и показывает итоговый экран. Смена раундов автоматом не происходит. Выход на главную из активной игры требует подтверждения и не увеличивает число завершённых игр.

Общий счёт верных ответов, рекорд серии и открытые достижения сохраняются сразу; лучший счёт и число полных игр — при завершении. Текущая сессия после перезагрузки не восстанавливается; сохранённая статистика и достижения остаются. Ключ: `rating-battle:stats:v1`, версия схемы: 1. Повреждённое сохранение сбрасывается к нулям. Если браузер запретил localStorage, игра продолжает работать и показывает сообщение, что сохранение недоступно.

Генератор сначала выбирает ещё не встречавшиеся допустимые сериалы, затем наиболее давно показанные. Одинаковые рейтинги и повтор одной записи в обеих карточках исключены, в том числе при замене. Датасет не ограничивает длину сессии.

## Публикация на GitHub Pages

1. Создать репозиторий на GitHub и загрузить содержимое проекта, включая CSV, `package-lock.json` и `.github/workflows/deploy.yml`. Не загружать `node_modules` и `dist`.
2. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
3. Отправить изменения в ветку `main` либо запустить workflow вручную на вкладке **Actions**.
4. После успешных проверок workflow соберёт и опубликует `dist`. Адрес будет в разделе Pages и в результате задания публикации.

`base: './'` в Vite позволяет публиковать приложение как в корне домена, так и в подкаталоге репозитория. Маршрутизация внутренняя, без путей URL, поэтому отдельный `404.html` не требуется. Для другой ветки изменить фильтр `branches` в workflow.

Публикуемая версия содержит мобильную компоновку с двумя карточками в отдельных строках, крупными кнопками и локальными постерами.

## Структура

```text
src/lib/data.ts          — чтение CSV, валидация, форматирование и сортировка
src/lib/game.ts          — пары, раунды, очки, комбо, жизни и бонусы
src/lib/appState.ts      — атомарные переходы приложения и завершение сессии
src/lib/achievements.ts  — условия и однократное открытие достижений
src/lib/storage.ts       — версия схемы, безопасное чтение и запись
src/components/         — экраны, рейтинг, модальные окна и постеры
src/styles.css          — Tailwind, аркадный стиль и адаптация
src/App.tsx             — загрузка, навигация, диалоги и уведомления
tests/                  — проверки на исходном датасете и DOM-сценарии
.github/workflows/      — проверка и публикация GitHub Pages
```

Тесты DOM проверяют взаимодействие, а не реальную отрисовку и геометрию браузера. В среде создания проекта браузерный предпросмотр недоступен; визуальная проверка реальных устройств отдельно не подтверждена.
